# Local transcription in WyspaFluent 0.9.5

Fresh installations include the 45.2 MB Zipformer English 20M model, enable local transcription and Stream Mode, and prepare the engine in the background. No account, terminal or initial model download is required. Existing users keep their chosen provider and model. Settings → Local models starts with the local transcription toggle, then GPU acceleration, the model manager, model comparisons and optional voice setup. Turning local mode off dims and disables the rest of the section. The GPU option is disabled when no compatible Vulkan GPU is detected. Local mode can be enabled before installing a model, so the manager remains reachable; dictation requires an installed model, but no voice profile.

The optional Whisper models come from OpenAI's Whisper family, converted to GGML by the whisper.cpp project. Q5/Q8 are quantized variants that reduce file size; they do not promise the same accuracy or CPU latency as full-precision weights. The original family was released in September 2022, Large v3 in November 2023, and Turbo in September 2024. See [OpenAI's model card](https://github.com/openai/whisper/blob/main/model-card.md) and [the conversion repository](https://huggingface.co/ggerganov/whisper.cpp).

Whisper models are downloaded from https://huggingface.co/ggerganov/whisper.cpp and pinned to repository revision `5359861c739e955e79d9a303bcbc70fb988958b1` and checked against pinned byte counts and SHA-256 hashes. They are stored in `%LocalAppData%\Wyspa\Models`. Downloads show progress, support cancellation, and become available only after complete verification. Cancelled/failed downloads remove their temporary files; transient network failures get up to three attempts, and retry restarts the download. The catalog is curated and versioned with the app, not an unverified live list. After downloading, inference has no model-host connection. A reachable host today is not an uptime guarantee. The manager lists every available model with its name, size, model-info button, installed state and a per-model Install/Remove button. Choose Use to select an installed model. Checkboxes select models for Install selected or Remove selected; mixed batches affect only missing or installed models respectively. Up to two downloads run together, each with its own progress bar and percentage. Cancel batch or app shutdown cancels outstanding work and removes incomplete files; completed installations/removals remain. Failures are reported per row and retain their selection for retry. Removing models pauses listening and refuses to delete files during an active capture. If the active model is removed, the next installed model becomes active. If none remain, local mode stays selected and requests an installation; Wyspa does not fall back to Groq.

Local mode covers dictation, SmartListen, Stream Mode, Scratchpad, Audio Files, Conversation and YouTube transcription. Conversation and YouTube keep separate libraries. YouTube still downloads video audio over the internet. Local speech uses sherpa-onnx 1.13.8 for the bundled Zipformer model and Whisper.net 1.9.1 / whisper.cpp for Whisper. GPU access is allowed by default when a compatible Vulkan adapter is detected and can be turned off. Whisper supports Vulkan; Faster-Whisper supports NVIDIA CUDA on a detected NVIDIA adapter. The other managed engines currently use CPU. GPU permission does not force GPU processing: current CPU/GPU measurements choose the faster comparable backend per model, preferring CPU for near ties and GPU failures. CPU inference remains available. Native 16 kHz mono capture bypasses FFmpeg; other formats are decoded locally. Temporary PCM is removed after processing. Local note timestamps are segment-level, so speaker boundaries are less precise than cloud word timestamps.

These are speech models, not general text-generation models. Groq Tone Re-write, AI intent interpretation, Stream Fix and summaries are not performed in local mode. Basic text cleanup and locally recognised keyboard commands remain available. Switching to Groq explicitly allows cloud transcription and text features again. Saved Groq settings and the encrypted key are retained.

Performance depends on hardware, model, audio and background work. Zipformer consumes incremental audio once and flushes the tail at stop. Whisper uses bounded overlapping windows; local mode no longer repeats the whole recording at stop. Groq keeps its separate snapshot/final-pass behavior. See [performance research and measurements](LOCAL_PERFORMANCE_RESEARCH.md).

Model removal is available in Settings. Models live outside the installation folder and survive app upgrades. Remove downloaded models before uninstalling if you want to reclaim that storage; the existing uninstall data choice concerns roaming settings/notes.

Build prerequisites: NuGet restores the pinned Whisper packages. Setup downloads the pinned Microsoft C++ redistributable only if its compatible x64 runtime is missing. The wizard checks SHA-256, Authenticode, product and version before running it. The .NET Desktop Runtime retains its existing on-demand setup flow. Neither runtime installer is embedded. `scripts/package.ps1` also runs `prepare-local-model.ps1` to obtain and hash-verify the bundled model; builds include the Vulkan runtime. End users do not run these scripts.


## Voice setup and testing

Setup starts the selected microphone only when Record passage is clicked. Each recording ends with Stop and test, Cancel, or a 45-second limit. The same audio is transcribed with and without personal vocabulary; the reference text is used only to score output, never supplied as a transcription prompt. Temporary audio is deleted after each test. Choose a language code; replace the English sample passages with your own passages for other languages. Use an English-only model only for English.

Word error uses word-level edit distance, ignoring punctuation and case. This is a small reading test, not a general accuracy guarantee; scripts without word separators are not adequately measured by this metric. First-pass timing includes model loading, so timing differences between baseline and hints are not a controlled speed comparison. Results may exceed 100% word error when there are many extra words.

Voice setup is optional. Saving after three successful passages applies language, vocabulary hints if they did not increase total test errors, and a conservative SmartListen silence interval estimated from reading pace (1200–1800 ms). It is not acoustic pause detection. Saved profile fields include model ID, timestamp, language, vocabulary and per-passage error/timing scores. Raw audio and recognised passages are not persisted by this setup. Delete profile removes vocabulary and scores; current SmartListen timing remains editable in Audio & Capture. Restart tests can compare another model while keeping the prior profile until a new one is saved.

This is configuration calibration and evaluation. It does not fine-tune model weights or create an accent, voice, tone or personality embedding. A few readings cannot establish that arbitrary speech recognition improves. For true acoustic fine-tuning, a separate training pipeline, sufficient labelled speech and evaluation would be needed; none is included here.

The bundled Zipformer model is English-only, trained on LibriSpeech, and has no automatic punctuation. It uses at most two CPU threads. Vocabulary hints are supported by Whisper, not Zipformer; Zipformer setup evaluates one recognition pass and tunes pause timing. Both engines keep the microphone inactive until the user starts recording. Removing the bundled model from Settings removes its per-user copy; the installer’s repair copy remains in the application folder. It is not automatically reinstalled after the initial setup flag has been saved.

Optional feature dependencies are downloaded automatically at first use: YouTube support (Deno 2.9.7) and in-person speaker models. Files are hash/size verified and cached in `%LocalAppData%\Wyspa\Dependencies`; existing valid bundled files are also accepted for offline upgrades. First use needs internet; cached speaker identification runs offline. Cancel pending can cancel speaker setup before capture begins. YouTube Cancel also cancels its support download.

## Hardware recommendations and provider comparison

Settings → Local models offers a hardware starting point and an optional performance comparison. CPU name/core count, RAM, a Vulkan GPU and its device-local memory are inspected locally. Compact Tiny Q5 is the starting point on capable GPU systems; constrained English streaming systems favour the included Zipformer. Larger models remain optional accuracy upgrades. Hardware suggestions have no invented latency values.

Compare Models measures every installed model in the catalog, with the active model first. The list is captured when testing starts; a spinning-lines indicator stays visible throughout preparation, testing and result saving. With GPU access enabled and detected, GPU-capable models receive separate CPU/GPU runs and result rows. The device column records the actual backend, including CPU fallback rather than treating a requested GPU as proof of GPU use. CPU-only engines are tested once. Models run sequentially to avoid competing for CPU/GPU/RAM, and each result is added as it completes. Compare with Groq stays disabled until a completed current local comparison has a successful installed result. It compares only the highest-scoring local result, reusing that local measurement, and sends the included 11-second public speech sample to the selected Groq transcription model with the saved key (four test requests, plus any transport retries). No user microphone recording is made or uploaded. The test never downloads models or changes providers. Applying a recommendation is an explicit action, and can download a missing suggested model.

The first test includes preparation/cache reuse and its first result; Avg. Result is the mean of three repeat passes. Groq includes upload, network, server processing and response; server compute is not separately reported. CPU seconds and resident RAM describe the app during the test, including unrelated app work and previously loaded models, and exclude GPU work/VRAM. These timings do not measure dictation-to-field or continuous-stream latency. Sample word errors ignore punctuation/case and do not establish accent or multilingual accuracy.

Recommendations favour models with comparable sample errors before comparing speed. A successful cloud result can win for materially lower latency or fewer errors within the short-dictation target. Close latency/quality results favour local offline processing; resource columns remain available for the user's decision. Results are stored as timings, errors and a hardware fingerprint, without transcript text or credentials. A GPU preference, driver or hardware change invalidates the recommendation. A different Groq model requires a new cloud comparison. Cloud timings older than 24 hours remain visible but are excluded from provider recommendations until retested. Testing and applying recommendations reserve listening; cancellation or shutdown releases it.

## Conversation transcription and speaker labels

Conversation uses the same selected ASR model/provider as ordinary dictation. Whisper/Zipformer weights transcribe speech; the current models do not directly output stable speaker identities. Computer-call mode uses microphone versus playback channels for You/Other-side labels. In-person mode adds pyannote segmentation and CAM++ speaker embeddings, sharing the sherpa-onnx runtime where applicable but using separate purpose-trained weights. These approximately 36 MB models download on first use and stay cached; they assign anonymous speaker labels, with the user's My room speaker selection mapping their own voice. Speaker matching remains experimental.

Sources: [OpenAI Whisper model card](https://github.com/openai/whisper/blob/main/model-card.md), [sherpa-onnx diarization models](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/models.html), [Groq speech endpoint](https://console.groq.com/docs/speech-to-text). Published server speed factors are not used as an estimate of a user's network latency.

## Additional downloadable models and wake phrases

The curated catalog now adds NVIDIA Parakeet TDT 0.6B v3 INT8 (670.5 MB, 25 European languages), Parakeet v2 English INT8 (661.2 MB), Moonshine Tiny English INT8 (124.0 MB), Moonshine Base English INT8 (286.9 MB), and Zipformer English streaming INT8 (73.4 MB). Sizes include all required weights and tokens, below the decimal 1.5 GB cap. Original publishers, licences and pinned ONNX-export revisions are shown in the model details. Downloads verify every file before activating the bundle; cancellation removes staging files. Alternative weights are not embedded in Setup.

Parakeet and Moonshine use the existing sherpa-onnx CPU engine with bounded threads. They do not use Whisper's Vulkan switch or vocabulary prompts in this build. Native Zipformer models use continuous stateful streaming; Parakeet/Moonshine use bounded-window recognition. Cold model loading, RAM and accuracy are different from download size; use the existing local/Groq comparison for timings on the actual PC. Parakeet/Moonshine exports currently return segment-level timing to Wyspa. Switching engines releases unused cached contexts.

There is no guaranteed 99.99% ASR accuracy. NVIDIA's v3 card reports 1.93% WER on LibriSpeech clean and 6.34% average across its English leaderboard datasets, with substantial variation by dataset/noise/language. Those results describe the original model/evaluation and are not a promise about an INT8 export, microphone, accent or short dictation. Sources: https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3 and https://k2-fsa.github.io/sherpa/onnx/pretrained_models/offline-transducer/nemo-transducer-models.html. Moonshine provenance: https://huggingface.co/UsefulSensors/moonshine and https://k2-fsa.github.io/sherpa/onnx/moonshine/models.html.

Wake Voice uses the local English word-level keyword spotter, followed by independent local word verification. Personal wake setup adds pronunciation examples for the selected microphone. The guided suite and matching policy are described below. No Python or command-line setup is required.

Enable wake phrases is available only in SmartListen. Say the phrase, wait for the ready tone, then dictate; the selected local/Groq transcription settings apply. Silence ends dictation and the detector rearms for another phrase. Wake audio is excluded from pre-roll; immediate speech before the ready cue can be missed. Failed preparation or an invalid phrase pauses detection. A bounded work queue and stream resets limit unattended monitoring memory; dropped frames reset partial keyword state.

Keyword model/decoder source: https://k2-fsa.github.io/sherpa/onnx/kws/index.html. Thresholds are detector settings, not probabilities or accuracy claims.


## Redux, SenseVoice and Faster-Whisper · October 2026

Parakeet Redux ONNX (417,712,821 bytes) is the eschmidbauer ONNX conversion of Moondream/NVIDIA Redux, CC BY 4.0. The CPU decoder uses the export's log-mel preprocessor, encoder, joint token/duration predictor and vocabulary. Language is automatic, and prompts are unsupported. Bounded 30-second recognition blocks avoid unbounded encoder memory for long recordings; timings are segment-level. The original Photon benchmarks are not measurements of this ONNX implementation. Sources: [original Redux model](https://huggingface.co/moondream/parakeet-redux), [ONNX export](https://huggingface.co/eschmidbauer/parakeet-redux-onnx).

SenseVoice Small INT8 (237,431,441 bytes) uses the sherpa-onnx export and existing CPU runtime. It supports Mandarin, Cantonese, English, Japanese and Korean with automatic language detection and inverse text normalization. Prompts are unsupported. Sources: [SenseVoice publisher](https://huggingface.co/FunAudioLLM/SenseVoiceSmall), [sherpa-onnx integration](https://k2-fsa.github.io/sherpa/onnx/sense-voice/index.html).

Faster-Whisper is an inference engine, not a separate acoustic architecture. Tiny English (78,090,594 bytes) and Base English (147,769,510 bytes) use SYSTRAN's converted OpenAI weights, CTranslate2 CPU INT8 or NVIDIA CUDA INT8/FP16. They support optional vocabulary prompts. Sources: [Faster-Whisper](https://github.com/SYSTRAN/faster-whisper), [CTranslate2 installation](https://opennmt.net/CTranslate2/installation.html), [Tiny weights](https://huggingface.co/Systran/faster-whisper-tiny.en), [Base weights](https://huggingface.co/Systran/faster-whisper-base.en).

Redux and Faster-Whisper share an isolated managed runtime. Its first-use download is 91,519,645 bytes: official Python 3.12.10 embeddable Windows x64 and pinned PyPI wheels. It does not run pip, install Python system-wide, change the global PATH or use a shell. A single process stays warm while its model is active, runs below normal priority with bounded threads, and is stopped when switching engines or quitting. Inference sets offline mode and loads verified local files; temporary PCM is deleted after processing/cancellation. The benchmark includes worker CPU time and RAM. Wheel metadata/licenses are retained.

Faster-Whisper CUDA can reuse visible compatible CUDA libraries. Otherwise its first GPU use downloads pinned NVIDIA cuBLAS/cuDNN wheels totaling 1,076,821,750 bytes, shared by both models; this extra runtime download is disclosed in model details. Libraries are cached outside Setup, with child-only DLL/PATH configuration. Verified extracted files remain cached; redundant downloaded archives are discarded. The model-size column lists complete model weights/tokenizer/config sizes, separately from shared runtimes. No extra models or worker/CUDA distributions are bundled in the installer.

CPU/GPU measurements use test format jfk-v2-devices, preserving the same included sample. Older results stay visible but need retesting for device choices. Backend selection only uses current matching hardware/GPU preference and successful actual-device evidence for that model; it ignores GPU fallback as GPU success and chooses CPU for near ties, worse GPU sample errors or failed GPU tests. It never changes the saved provider/model automatically. This short English sample is provisional evidence, not a multilingual/accent/long-audio guarantee.

Both model tables use horizontal scrolling and viewport-aware maximum heights to keep their bottom scrollbars reachable in short windows. Cells are centered vertically. Clicking a row does not select/highlight it; only checked model-manager rows receive an accent border. Model-info buttons open each publisher's model card/project page.


## Ranked comparisons and guided wake practice · October 2026

Comparison rows show Model, Device, Avg. Result, 1st Result, CPU Time, RAM, Errors and a Score out of 100. Score is `80 × (1 − word-error fraction)^4 + 20 / (1 + mean seconds)`, clamped for valid error fractions and rounded to one decimal. Failed tests have no score. The rule strongly penalizes sample errors; speed distinguishes similarly accurate models. Completed tests sort highest first and highlight the winner. Exact score ties favor local over cloud. This score does not measure universal model accuracy. Format jfk-v3-ranking invalidates older median-based/device-only evidence for current recommendations.

Groq comparison adds four sample requests only after Compare Models has completed. It displays just the top installed local result and Groq; all local CPU/GPU measurements remain saved for backend selection. Cloud has its own timestamp, and cancelled or failed preparation cannot overwrite previous completed measurements. A partial/cancelled local sweep does not enable Groq comparison or declare an overall winner.

Wake Voice exposes an English phrase, Enable wake phrases and an owned popup Personal wake setup wizard, available only in SmartListen. The 14-step suite starts with room sound, then alternates wake and non-wake readings. Only three readings ask for the phrase alone; two different requests, everyday sentences, a near match and the final word on its own add context and negative evidence. Four sentence families vary new setups and adjustment checks. Four fresh readings check the frozen candidate profile through the same continuous detector path used during monitoring: phrase, new request, ordinary speech and near match. Successful fresh checks do not train the profile. A missed check becomes a labelled teaching example: Wyspa adds pronunciation/negative evidence, relaxes or tightens matching strictness and restarts all four checks with fresh recordings. Adjustment is bounded to six additional teaching examples; unresolved separation keeps personalization inactive. Successful completion applies the calibrated sensitivity and enables monitoring when transcription is available.

The wizard has an introduction, focused sample screens and a completion page showing learned pronunciations and applied strictness. Room sound lasts three seconds. Other samples finish after speech and a pause against the learned room level; a five-second phrase/eight-second sentence cap and Finish/Discard controls remain. Loud background sound may require Finish. The endpoint is a sample-count/RMS convenience, not a neural speech classifier. Closing pauses setup, discards an active recording and keeps completed examples. Listening is reserved for the whole wizard session so ordinary dictation/hotkeys cannot start between samples. Quiet/clipped/short readings receive actionable feedback. Completed steps resume after reopening; changing the phrase or microphone starts a fresh suite. Restart setup deletes saved enrollment features. Unrelated settings/preview work respects the microphone reservation and does not issue media commands.


## Speech-based stopping and two-stage wake detection

SmartListen-specific threshold, live-level preview, silence interval and listening on/off controls are shown only in SmartListen mode. The single hotkey title follows the mode: Toggle Wyspa, Hold Hotkey, or SmartListening On/Off.

Wake Voice uses a continuous, one-thread keyword spotter followed by a short local word-verification pass when a candidate appears. Verification uses pinned Whisper Tiny English Q5 with no transcript/personal prompt, a bounded short audio context, two CPU threads and a token limit. Up to four seconds of recent wake audio remain in memory only. Token timestamps isolate the candidate with final-token allowance and short quiet padding; short phrases use a small decoding budget. If that word check fails, the original full window is checked and one additional 200 ms of incoming audio may be requested. No candidate bypasses word verification. The usual local models/account choices are not changed by verification. Matching existing Tiny downloads are reused; missing verification weights download once (32.2 MB) alongside the 6.3 MB keyword model. Silero VAD adds approximately 0.64 MB, making total initial wake preparation about 39 MB. These weights stay out of Setup.

Silero speech activity, rather than raw loudness, updates the recording's monotonic silence clock when PCM is available. The 100 ms endpoint timer ends capture independently of level callbacks. The start threshold does not determine neural speech stopping; if speech detection is unavailable, a bounded level fallback uses an absolute positive floor, so a zero threshold cannot classify digital silence as voice. Audio frames from an old recording cannot extend the next session. Non-streaming recordings now emit the same capture-stopped event as streams, allowing wake rearming and hotkey media restoration when microphone capture ends.

The design follows public low-latency streaming KWS and staged verification approaches, using available local models rather than proprietary assistant weights: [Google streaming KWS](https://research.google/pubs/streaming-keyword-spotting-on-mobile-devices/), [Amazon two-stage wake detection](https://www.amazon.science/blog/alexa-scientists-present-two-new-techniques-that-improve-wake-word-performance), [Silero integration](https://k2-fsa.github.io/sherpa/onnx/vad/silero-vad.html). A PC microphone does not reproduce a smart speaker's microphone array, echo cancellation, training corpus or hardware. Accent/noise/media-echo performance still requires real-microphone acceptance.


## Personal wake matching · 8 October 2026

Enrollment stores up to six compact cepstral trajectories (normally three), a background RMS estimate, threshold results and up to three repeatedly observed plausible transcription variants. Normalized spectral features and bounded dynamic time warping make matching less dependent on volume and timing. The similarity threshold must separate training positives from negative readings; otherwise the personal acoustic fallback stays disabled. Stable spelling/pronunciation variants need at least two positive phrase-only examples, cannot collide with observed non-wake examples, and need fresh checks. Phonetic normalization includes common voiced/unvoiced spelling differences such as whisba/whispa/whisper. Positive samples are not rejected merely for failing to transcribe as the canonical spelling; empty, clipped or inaudibly quiet recordings still get microphone feedback. These are supervised phrase variants, not arbitrary trigger words.

The continuous keyword model remains the primary detector. When a validated profile matches the configured phrase and microphone, a short speech/pause segment can propose an additional personal candidate. Learned variants are added directly to the live keyword decoder; changing the variant set rebuilds its stream. Both paths must pass independent word verification against the typed phrase or its learned variants. Matching a voice pattern alone cannot activate dictation. This adapts a local detector profile; it does not fine-tune neural model weights or authenticate the speaker.

The approach is informed by [query-by-example enrollment research](https://arxiv.org/abs/1910.05171) and [openWakeWord's speaker/environment verifier guidance](https://github.com/dscripka/openWakeWord/blob/main/docs/custom_verifier_models.md). Wyspa uses its own compact feature matcher with its existing keyword/Whisper verification pipeline; it does not implement the paper's posterior/FST algorithm or openWakeWord's embedding classifier. Those sources do not establish accuracy for this implementation. Alexa-level reliability remains a real-microphone acceptance target, requiring independent accent, distance, noise, media-echo and unattended false-trigger measurements.


## Varied enrollment and measured wake optimisation

The suite protocol is versioned separately from the existing detector/profile identifiers. Validated older profiles remain usable; incompatible pending readings restart with the same chosen phrase. Current pending readings preserve their sentence-family seed so reopening does not silently change prompts. Wake detection continues to use the dedicated English 3.3M spotter and independent Tiny English Q5 verification; the actual dictation provider/model remains the user's selection.
